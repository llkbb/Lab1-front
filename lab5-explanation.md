# Лабораторна робота №5: повне пояснення

## 1. Призначення роботи

Лабораторна робота №5 не додає окрему бізнес-функцію. Вона перевіряє якість уже створеного фронтенду з трьох боків:

1. адаптивність — чи зручно користуватися сторінкою на різних екранах;
2. кросбраузерність — чи працюють використані технології в різних браузерах;
3. ефективність — наскільки швидко та стабільно сторінка завантажується і відображається.

Аудиту піддано сторінки [`index.html`](./index.html), [`courses.html`](./courses.html) і [`feedback.html`](./feedback.html), створені в попередніх лабораторних роботах.

---

## 2. Що таке адаптивність

Адаптивний дизайн змінює структуру та розміри інтерфейсу відповідно до ширини viewport. Користувач не повинен збільшувати сторінку або прокручувати її горизонтально, щоб прочитати текст чи натиснути кнопку.

У цьому проєкті адаптивність забезпечується:

- метатегом viewport;
- CSS Grid і Flexbox;
- відносними одиницями;
- `clamp()`;
- медіа-запитами;
- гнучкими зображеннями;
- переходом багатоколонкових блоків в одну колонку.

---

## 3. Viewport-метатег

У кожній сторінці є:

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

`width=device-width` встановлює ширину layout viewport, рівну ширині пристрою. `initial-scale=1.0` задає початковий масштаб без автоматичного збільшення.

Без цього метатега мобільний браузер може використовувати умовну ширину близько 980 px, тому медіа-запити працюватимуть не так, як очікується.

---

## 4. Брейкпоінти

У [`styles.css`](./styles.css) використано кілька груп адаптивних правил:

### До 850 px

Основна сітка переходить у вертикальний вигляд:

- hero стає одноколонковим;
- вступний блок стає одноколонковим;
- картки курсів розташовуються одна під одною;
- footer стає одноколонковим;
- навігація займає окремий рядок.

### До 700 px

Додатково:

- header вирівнюється по верхньому краю;
- кнопки займають доступну ширину;
- flip-картка центрується;
- tooltip переміщується під textarea.

### До 560 px

Для телефонів:

- зменшуються відступи header;
- заголовки залишаються читабельними;
- форма переходить в одну колонку;
- кнопки можуть переноситися на новий рядок.

### До 420 px

Для дуже вузьких екранів:

- main отримує відступи `16 px`;
- зменшується розмір бренду та навігації;
- розмір заголовка обмежується через `clamp()`;
- форма отримує менші внутрішні відступи.

## 5. Усунення горизонтального переповнення

Під час першої перевірки таблиця на головній сторінці мала мінімальну ширину `730 px`. Це було необхідно для збереження читабельності таблиці, але могло створювати горизонтальне переповнення документа на телефоні.

Таблиця вже знаходиться в контейнері:

```css
.table-wrap {
  overflow-x: auto;
}
```

Тому таблиця може прокручуватися всередині власного контейнера. Додатково для документа використано:

```css
html {
  overflow-x: hidden;
}

body {
  overflow-x: hidden;
}
```

Це не обрізає саму таблицю, а не дозволяє її широкому вмісту збільшувати ширину всього документа.

Після зміни на ширинах `320`, `768` і `1440 px` горизонтальний overflow відсутній на всіх трьох сторінках.

## 6. Гнучкі зображення

До стилів додано:

```css
img {
  max-width: 100%;
}

.hero-figure img,
.course-card img {
  display: block;
  height: auto;
}
```

`max-width: 100%` не дозволяє зображенню бути ширшим за контейнер. `height: auto` зберігає пропорції.

Для зображень у HTML додано `width` і `height`, наприклад:

```html
<img
  src="..."
  alt="..."
  width="700"
  height="467"
  loading="lazy"
  decoding="async">
```

Розміри дають браузеру можливість зарезервувати місце до завантаження картинки. Це зменшує CLS, тобто зміщення елементів під час завантаження.

---

## 7. Lazy-loading і пріоритет зображень

Зображення карток курсів і зворотної сторони авторської картки не потрібні для першого екрану. Для них використано:

```html
loading="lazy"
decoding="async"
```

`loading="lazy"` відкладає завантаження до наближення елемента до viewport. `decoding="async"` дозволяє декодувати картинку без блокування основного потоку.

Hero-зображення є частиною першого екрану, тому для нього використано:

```html
fetchpriority="high"
```

Це повідомляє браузеру, що зображення важливе для швидкого візуального відображення сторінки.

---

## 8. Мобільна навігація

На ширині до `850 px` навігація переходить на окремий рядок:

```css
.site-header nav {
  order: 3;
  width: 100%;
  justify-content: space-between;
  overflow-x: auto;
}
```

На ширині до `700 px` додатково:

```css
.site-header nav {
  gap: 16px;
  justify-content: flex-start;
}

.site-header nav a {
  white-space: nowrap;
}
```

Посилання не стискаються всередині слова, а навігація залишається доступною навіть на вузькому екрані.

---

## 9. Адаптивна форма

Форма зворотного зв'язку використовує CSS Grid. У звичайному режимі поля можуть бути розташовані у дві колонки, а в медіа-запиті:

```css
.form-grid {
  grid-template-columns: 1fr;
}
```

кожне поле займає окремий рядок. Це зручніше для введення даних на телефоні та зменшує ризик випадкового натискання не в те поле.

Кнопки форми використовують flex-wrap, тому на вузьких екранах можуть перейти на новий рядок.

---

## 10. Адаптивний tooltip

На широкому екрані підказка для поля «Детально» розміщена праворуч:

```css
.field-tooltip {
  left: calc(100% + 16px);
  bottom: 12px;
}
```

На ширині до `850 px` підказка переміщується під полем:

```css
@media (max-width: 850px) {
  .field-tooltip {
    left: 0;
    bottom: -62px;
  }
}
```

Це запобігає виходу tooltip за праву межу viewport.

---

## 11. Підтримка reduced motion

Для користувачів, які в налаштуваннях системи вимкнули анімації, додано:

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    scroll-behavior: auto !important;
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

Це стосується падаючих іграшок, flip-картки, tooltip, акордеона та hover-переходів. Функціональність зберігається, але рухомі ефекти майже не анімуються.

## 12. Кросбраузерність

Кросбраузерність означає передбачувану роботу сайту в різних браузерах.

### HTML

Використано стандартні HTML5-елементи:

- `header`;
- `nav`;
- `main`;
- `section`;
- `article`;
- `footer`;
- `form`;
- `fieldset`;
- `label`;
- `input`;
- `textarea`;
- `select`;
- `button`.

Сучасні браузери підтримують ці елементи. Internet Explorer розуміє більшість із них на базовому рівні, але має обмеження для сучасних CSS і accessibility-механізмів.

### CSS

Основні сучасні можливості:

- Flexbox;
- Grid;
- custom properties;
- `clamp()`;
- CSS transforms;
- `perspective`;
- `backdrop-filter`;
- media queries;
- `prefers-reduced-motion`.

Chrome, Edge, Firefox, Safari та Opera підтримують ці можливості з актуальними версіями браузерів. Internet Explorer не підтримує CSS Grid у сучасному варіанті, CSS variables, `clamp()`, `backdrop-filter` і `prefers-reduced-motion`.

### JavaScript

Для інтерактивності використано стандартні API:

- `document.querySelector`;
- `addEventListener`;
- `classList.add`;
- `classList.remove`;
- `classList.toggle`;
- `getAttribute`;
- `setAttribute`;
- `DOMContentLoaded`.

Ці API мають широку підтримку, але сучасні accessibility-атрибути й окремі CSS-можливості потрібно перевіряти окремо.

## 13. Метрики ефективності

Для локальної перевірки використано Navigation Timing API:

```js
const navigation = performance.getEntriesByType("navigation")[0];
const domContentLoaded =
  navigation.domContentLoadedEventEnd - navigation.startTime;
const loadEvent =
  navigation.loadEventEnd - navigation.startTime;
```

У результаті отримано:

| Сторінка | DOMContentLoaded | Load event |
|---|---:|---:|
| `index.html` | 69 ms | 70 ms |
| `courses.html` | 60 ms | 61 ms |
| `feedback.html` | 51 ms | 59 ms |

Це вимірювання локального запуску, тому воно не враховує повністю мережеву затримку реального хостингу. Для production-аудиту використовують Lighthouse, PageSpeed Insights, WebPageTest, Sentry, New Relic або Datadog.

### Основні метрики

- **LCP** — час появи найбільшого видимого елемента;
- **INP** — швидкість реакції на взаємодію;
- **CLS** — стабільність розташування елементів;
- **FCP** — час появи першого контенту;
- **TTFB** — час отримання першого байта;
- **Total Blocking Time** — час блокування основного потоку.

### Можливі причини низьких показників

1. Зображення завантажуються із зовнішнього Unsplash.
2. Google Fonts підключається через зовнішній stylesheet.
3. Великі зображення можуть передаватися у більшій якості, ніж потрібно на телефоні.
4. CSS-анімації можуть збільшувати навантаження на compositing.
5. Локальний `file://`-запуск не повністю імітує production-сервер.

У роботі вже виконано базову оптимізацію: lazy-loading, `decoding="async"`, резервування розмірів, `fetchpriority`, адаптивні зображення та reduced-motion.

## 14. Як продемонструвати лабораторну

1. Відкрити [`index.html`](./index.html).
2. Натиснути `F12`.
3. Увімкнути Device Toolbar.
4. Перевірити ширини `320 px`, `768 px`, `1440 px`.
5. Перейти на `courses.html` і перевірити каталог та акордеон.
6. Перейти на `feedback.html` і перевірити форму та tooltip.
7. У Console виконати:

```js
document.documentElement.scrollWidth <= window.innerWidth;
```

Очікуваний результат — `true`.

8. Для перевірки reduced motion у DevTools увімкнути відповідну емуляцію медіа-функції.
9. У Lighthouse виконати аудит Performance, Accessibility, Best Practices і SEO.

---

## 15. Коротке усне пояснення

> У лабораторній роботі я перевірив вебпортал із попередніх лабораторних на трьох типах екранів: 320, 768 і 1440 пікселів. Для покращення адаптивності додав додаткові медіа-запити, гнучкі зображення, мобільну поведінку навігації та адаптацію форми. Горизонтальний overflow був усунутий, а таблиця залишилася доступною для прокручування всередині власного контейнера. Для продуктивності додав lazy-loading, асинхронне декодування зображень, атрибути їхніх розмірів і високий пріоритет hero-зображення. Також проаналізував підтримку HTML, CSS і JavaScript у сучасних браузерах та Internet Explorer. Базові метрики завантаження виміряв за допомогою Navigation Timing API й описав чинники, які можуть впливати на Lighthouse.
